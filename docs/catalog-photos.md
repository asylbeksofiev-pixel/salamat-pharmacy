# Фото товаров каталога

Процесс поиска, проверки и публикации фотографий для 13 347 товаров из `public.pharmacy_products`.
Файлы изображений хранятся в публичном **Vercel Blob**. В Neon попадают только URL и небольшие метаданные
(`catalog_images`), в GitHub — ни одного изображения. Результаты пробного прогона: `docs/catalog-photos-dry-run.md`.

## Коротко

```bash
npm run photos -- process --limit 500
```

```bash
npm run photos -- report
```

```bash
npm run photos -- publish --manifest .photo-work/review.csv --sources salamat,off --confirm-rights --production
```

* `process` читает товары порциями (только чтение), ищет кандидатов, проверяет права, скачивает **только разрешённые**
  фото, делает WebP/AVIF и решает: `approved`, `needs_review` или `missing`. Ничего не загружает и ничего не пишет в Neon.
  Ctrl+C останавливает процесс после текущих товаров. Следующий запуск продолжает с последнего завершённого `id`.
* `report` пересобирает `manifest.csv`, `manifest.json` и `report.md` из журнала.
* `publish` загружает в Blob варианты строк со статусом `approved` (присвоенным правилами или проверяющим) и записывает
  их URL в `catalog_images`. Без `--confirm-rights` и явного списка `--sources` команда не работает. Для нелокальной базы
  дополнительно нужен `--production`.

Запускать на рабочем компьютере или в CI. **Не в Vercel Function и не при открытии страницы:** полный прогон занимает
часы из-за пауз между запросами к источникам.

## 1. Источники и права

Проверено 18.11.2026.

| Приоритет | Источник | Поиск | Право на фото | Что делает конвейер |
|---|---|---|---|---|
| 1 | Файлы SALAMAT или производителя (папка `--inbox` + `photos.csv`) | по `product_id` или штрихкоду | Указывается в каждой строке (`permission`): «собственная съёмка», «письмо № … от …» | Скачивает, проверяет, принимает автоматически, если характеристики не противоречат названию |
| 2 | НКТ, https://nct.gov.kz | **только по названию** (см. ниже) | **Не предоставлено.** Пользовательское соглашение (`/api/auth/users/user_terms/`, п. 7.1, 7.4) не даёт лицензии на повторное использование; фото загружают поставщики, они же отвечают за права | Сохраняет ссылку на карточку и фото для ручной проверки и запроса разрешения. Фото **не скачивает**, пока не задано `NCT_IMAGE_PERMISSION` |
| 3 | Open Food Facts / Open Beauty Facts / Open Products Facts | по точному штрихкоду | CC BY-SA 3.0, обязательна атрибуция «… contributors» и ссылка; по условиям сайта на упаковке могут быть элементы, защищённые правами третьих лиц | Скачивает, проверяет. Подпись «Фото: Open Food Facts contributors, CC BY-SA 3.0» со ссылкой на карточку выводится на сайте |

### Что удалось установить по НКТ

* Каталог — Angular-приложение. API на том же домене: `https://nct.gov.kz/api/…`. Чтение без авторизации работает:
  * `POST /api/core/products/search/?limit=&offset=` с телом `{"q": "…"}` — поиск по названию;
  * `GET /api/core/products/{id}/` — карточка;
  * публичная страница товара: `https://nct.gov.kz/#/products/{id}`.
* В карточке есть фото (`images[].image_url`, `https://nct.gov.kz/media/products/…`), `gtin`, `kztin_code`, `ntin_code`,
  форма выпуска, состав, производитель.
* **Поиска по штрихкоду через публичный интерфейс нет.** `GET /api/core/tin/by-xtin/?xtin=` отвечает `xtin not found`
  даже для кодов, которые есть в каталоге. Поиск по числовому штрихкоду падает с HTTP 500 примерно через 30 с.
  У лекарств поле `gtin` обычно пустое: идентификаторами служат NTIN и KZTIN.
* Раздел «Открытые данные» (`/opendata/api/datasets/`) требует входа в систему. «Open API» (Postman-документация по ссылкам
  со страницы) предназначен для регистрации и обновления карточек участниками. API Национального каталога маркируемых товаров
  (nationalcatalog.kz, `a.nc.ismet.kz`) выдаёт `apikey` зарегистрированным участникам оборота и ограничивает частоту запросов
  («API-Usage-Limit», 429 + `Retry-After`). Авторизацию и ограничения конвейер не обходит.
* Лимитов для публичного сайта НКТ не опубликовано, поэтому пауза — 2 с между запросами.

**Как получить фото из НКТ законно:** письменное разрешение правообладателя (производителя или поставщика, загрузившего
фото) либо оператора каталога на повторное использование. Разрешение на весь каталог записывается в `NCT_IMAGE_PERMISSION`
(например, «Письмо АО … № … от …»), после чего нужные товары перезапускаются с `--force`. Разрешение отдельного производителя
удобнее оформить через папку SALAMAT: его файлы и номер письма идут в `photos.csv`.

## 2. Артикул и штрихкод

`article` не уникален и не всегда штрихкод. Формат проверяется до любого поиска (`src/lib/catalog-photos/barcode.ts`).
Выборка из 528 товаров production:

| Вид | Доля | Поиск по штрихкоду |
|---|---|---|
| EAN-13 / UPC-A / EAN-8 / GTIN-14 с верной контрольной цифрой | 97,2 % | да |
| Внутренний код магазина (GS1 «restricted circulation»: 02…, 04…, 20…–29…) | 2,3 % | нет — код уникален только внутри магазина |
| Неверная контрольная цифра | 0,4 % | нет |
| Нецифровой артикул («Комплектующая для №100») | 0,2 % | нет |

Товары с одинаковым артикулом и разными характеристиками (определяются запросом к базе) никогда не получают фото
автоматически.

## 3. Правила сопоставления

`src/lib/catalog-photos/match.ts`. Фото принимается автоматически (`approved`), только если выполнено **всё** сразу:

1. штрихкод кандидата совпадает с артикулом, а артикул — валидный глобальный GTIN;
2. каждая характеристика из названия товара подтверждена кандидатом: дозировка (`500mg`, `120mg/5ml`, `20%`, `2000iu`),
   форма (таблетки, капсулы, раствор, …), объём или масса (`100ml`, `35g`), фасовка (`№20`, `60 caps`);
3. источник даёт право на повторное использование;
4. файл прошёл проверки (тип, размер, содержимое);
5. артикул не принадлежит товарам с другими характеристиками, и то же изображение не найдено для другого товара.

Всё остальное получает `needs_review` с перечнем причин (`reasons`) и оценкой `confidence`. Если кандидата нет —
`missing`. Пустой или битый файл при точном штрихкоде — `rejected`. Похожая упаковка не подставляется никогда,
изображения не генерируются. Файл, который SALAMAT привязал к конкретному `product_id`, принимается, если указанные в
`photos.csv` характеристики не противоречат названию.

Коды причин в манифесте:

| Код | Значение |
|---|---|
| `barcode_not_confirmed` | кандидат найден по названию, штрихкод не совпал или не указан |
| `article_instore`, `article_bad_check_digit`, `article_not_numeric` | артикул не годится для поиска по штрихкоду |
| `mismatch_<dosage/form/content/count>:A≠B` | характеристика противоречит названию (другая упаковка) |
| `unverified_<…>` | источник не указывает характеристику — подтвердить по фото может только человек |
| `reuse_rights_not_confirmed` | нет права на повторное использование (НКТ без разрешения) |
| `source_has_no_photo` | карточка есть, фото нет |
| `same_candidate_for_different_products`, `same_image_for_different_products` | один кандидат подошёл к разным товарам (например, вкусам одной линейки) |
| `article_shared_with_N_different_products` | этот артикул в таблице у товаров с другими характеристиками |
| `image_too_small`, `image_low_resolution`, `image_blank`, `image_corrupt`, `image_not_image` | проблемы файла |
| `nct_unavailable`, `openfacts_unavailable` | источник не ответил; при следующем запуске товар обрабатывается снова |

## 4. Изображения

`scripts/catalog-photos/image.ts`:

* скачивание только по https, не больше 15 МБ, тип по заголовку **и** по содержимому (JPEG, PNG, WebP, AVIF, HEIF, GIF, TIFF);
* длинная сторона меньше 300 px — блокируется, меньше 600 px — на проверку; пропорции больше 3:1 — на проверку;
  однотонная картинка (заглушка) — блокируется;
* варианты: длинная сторона **400 и 800 px**, **WebP** (q82) и **AVIF** (q55). Пропорции сохраняются, увеличения нет,
  применяется EXIF-поворот, прозрачность заливается белым, метаданные удаляются, лёгкая резкость для мелкого текста упаковки;
* дедупликация: один и тот же файл (по SHA-256) обрабатывается один раз, повторный URL не скачивается.

Имена в Blob предсказуемы: `catalog/products/<product_id>/v<версия>-<400|800>.<webp|avif>`. Версия растёт, только когда
меняется содержимое (SHA-256), поэтому повторная публикация не перезаписывает файлы (`allowOverwrite: false`), а
кэширование на год безопасно.

## 5. Манифест

`.photo-work/manifest.csv` (UTF-8 с BOM, открывается в Excel) и `manifest.json`. Поля из задания: `product_id`, `article`,
`name`, `image_url` (заполняется после публикации), `source_page`, `source_name`, `license_or_permission`, `attribution`,
`match_method` (`barcode_exact`, `assigned_by_salamat`, `name_search`, `none`), `confidence`, `review_status`, `checked_at`.

Дополнительно: `reasons`, `article_kind`, `candidate_name`, `candidate_barcode`, `candidate_manufacturer`,
`candidate_form`, `candidate_dosage`, `candidate_volume`, `candidate_pack`, `product_attributes`, `candidate_attributes`,
`original_image_url`, `image_sha256`, `image_width`, `image_height`, `original_bytes`, `variant_bytes`, `blob_prefix`,
`image_version`, `local_preview` (локальный файл 800 px для проверки), `source_code`, `other_candidates`.

**Ручная проверка:**

1. Скопируйте `manifest.csv` в `review.csv`: `report` пересоздаёт `manifest.csv`, и правки в нём потеряются.
2. Откройте `local_preview` и `source_page`. Проверьте название, дозировку, форму, объём и фасовку на упаковке.
3. Поставьте `review_status` = `approved` или `rejected`.
4. Опубликуйте: `npm run photos -- publish --manifest .photo-work/review.csv --sources … --confirm-rights`.

Опубликовать можно только строки со скачанным файлом (`image_sha256`). Фото НКТ без разрешения не скачиваются,
поэтому опубликовать их по ошибке нельзя.

## 6. База: `catalog_images`

Миграция `prisma/migrations/20261118170000_catalog_images_product_id` — минимальное изменение существующей таблицы:

* ключ — `product_id` (уникальный `id` из `pharmacy_products`) вместо `barcode`: одинаковые артикулы больше не дают
  одно фото разным товарам. `barcode` остаётся необязательным полем с индексом;
* новые поля: `attribution`, `review_status` (`approved` / `needs_review` / `rejected`, ограничение CHECK), `match_method`,
  `confidence`, `image_version`, `image_sha256`, `image_width`, `image_height`, `checked_at`;
* прежние строки по штрихкоду: если штрихкод принадлежит ровно одному товару, строка привязывается к нему со статусом
  `needs_review` (такие фото проверялись только по штрихкоду и скрыты до проверки). Остальные переносятся в
  `catalog_images_unmapped` — данные не удаляются;
* `public.pharmacy_products` только читается.

Сайт (`src/server/catalog-items.ts`) присоединяет фото по `ci.product_id = pharmacy_products.id` и только при
`review_status = 'approved'`. Собственный столбец `image_url` в `pharmacy_products`, если появится, имеет приоритет.

## 7. Сайт

* `ProductImage` распознаёт фото из Blob и выводит `<picture>` с AVIF и WebP (400w/800w) и `sizes`. Оптимизация Next.js
  на лету не используется — файлы уже подготовлены. Карточки и списки грузятся лениво (`loading="lazy"`), главное фото
  страницы товара — сразу (`fetchPriority="high"`).
* Миниатюры в списке каталога берут вариант 400 px (`sizes="56px"`), тоже лениво.
* `next.config.ts`: `images.remotePatterns` разрешает `https://*.public.blob.vercel-storage.com/catalog/**`.
  CSP `img-src … https:` уже позволяет загрузку.
* Подпись для фото с лицензией CC BY-SA: «Фото: Open Food Facts contributors, CC BY-SA 3.0. Упаковка может отличаться.»
  со ссылкой на карточку источника. У собственных фото SALAMAT подписи нет.

## 8. Повторяемость

| Что | Как |
|---|---|
| Порции | `--batch 50` (до 200), keyset по `id`, каждый запрос — транзакция `READ ONLY` |
| Остановка и продолжение | `state.json` хранит последний завершённый `id`; `results.jsonl` — по строке на товар; уже обработанные товары пропускаются (`--force` — заново, `--restart` — с начала) |
| Паузы | отдельная очередь на каждый хост: Open Food Facts 2,5 с (при 429 интервал растёт ×1,5 до 30 с), изображения OFF 0,3 с, НКТ 2 с, сайт SALAMAT 0,5 с |
| Повторы | 408/425/429/502/503/504 и сетевые ошибки — до 4 повторов с удвоением паузы, `Retry-After` учитывается |
| Кэш | ответы источников (включая «не найдено») хранятся 14 дней в `http-cache/`, поэтому продолжение не повторяет запросы |
| Журнал | `journal.jsonl`: начало и конец запуска, каждый товар, повторы, ошибки, публикации |
| Отчёт | `report.md`: статусы, причины, источники, форматы артикулов, размеры файлов, примеры |

Рабочая папка `.photo-work/` (оригиналы, варианты, журнал) в `.gitignore`.

## 9. Переменные окружения

| Переменная | Для чего |
|---|---|
| `DATABASE_URL` или `PHOTOS_DATABASE_URL` | чтение `pharmacy_products` (для `process` достаточно роли только на чтение), запись `catalog_images` при `publish` |
| `BLOB_READ_WRITE_TOKEN` | только для `publish` (Vercel → Storage → Blob) |
| `PHOTOS_INBOX_DIR` | папка с файлами SALAMAT/производителей и `photos.csv` (`product_id` или `barcode`, `file`, `source_name`, `permission`, `attribution`, `name`) |
| `NCT_IMAGE_PERMISSION` | реквизиты письменного разрешения на фото НКТ; без него фото НКТ не скачиваются |
| `PHOTO_BOT_CONTACT` | контакт в User-Agent (Open Food Facts просит указывать приложение и контакт); по умолчанию — адрес сайта |

За корпоративным прокси Node 22 нужно запускать с `NODE_USE_ENV_PROXY=1`.

## 10. Объём, время и стоимость

Исходные данные: средний комплект из 4 файлов — **113 КБ** (400.webp 17 КБ, 800.webp 54 КБ, 400.avif 11 КБ,
800.avif 31 КБ; по dry run).

| | Если фото у 2 000 товаров | Если фото у всех 13 347 |
|---|---|---|
| Хранилище Blob | ≈ 0,22 ГБ | ≈ 1,5 ГБ |
| Загрузки (advanced operations, 4 на товар) | 8 000 | 53 400 |
| Строки в Neon | ≈ 1 МБ | ≈ 5 МБ |

Тарифы Vercel Blob (https://vercel.com/docs/vercel-blob/usage-and-pricing): хранение $0,023 за ГБ в месяц, загрузки $5 за
1 млн, чтения с промахом кэша $0,40 за 1 млн, трафик $0,05 за ГБ. На Pro трафик Blob входит в 1 ТБ CDN. Hobby включает
1 ГБ, 2 000 загрузок и 10 ГБ трафика в месяц, и это **жёсткий лимит**. При Pro полный набор стоит меньше $0,05 в месяц за
хранение и около $0,27 разово за загрузку. На Hobby за месяц можно опубликовать не больше ~500 товаров
(2 000 загрузок / 4 файла), а 1,5 ГБ превышает лимит хранилища.

Трафик: страница каталога с 24 миниатюрами (400.avif) — около 0,25 МБ, фото на странице товара (800.avif) — около 31 КБ.
Например, 50 000 просмотров каталога и 50 000 просмотров товаров в месяц — около 14 ГБ. Это больше лимита Hobby и
незначительно для Pro.

Время полного `process`: ограничено паузами Open Food Facts (2,5 с, три сайта параллельно) и НКТ (2 с). Получается около
2,5–3 с на товар, **9–10 часов** на 13 347 товаров. Прогон можно останавливать и продолжать. Для массового чтения
Open Food Facts рекомендует свои ежедневные выгрузки данных: их подключение сократит время до минут.
