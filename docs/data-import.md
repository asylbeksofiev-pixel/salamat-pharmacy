# Импорт ассортимента, цен и остатков

Каталог наполняется только из разрешённых источников SALAMAT: файл выгрузки (CSV/XLSX) или API учётной системы.
Данные i-Teka, Биосферы и Pharmapay не импортируются (см. `docs/source-audit.md`).

## Способы загрузки

| Способ | Где | Объём |
|---|---|---|
| Админ-панель → «Импорт / экспорт» | `/admin/import` (роль «Менеджер каталога» или Super Admin) | до 10 МБ, до 50 000 строк |
| Консоль | `npm run import:file -- выгрузка.xlsx --source-code salamat-1c --source-name "1С SALAMAT" [--publish] [--apply]` | то же ограничение строк; файл больше 10 МБ разделите |
| API учётной системы | `CATALOG_API_URL` (+ `CATALOG_API_TOKEN`), кнопка «Получить из API» | см. ниже |

Все способы идут через один конвейер: **проверка → предпросмотр → применение**. До нажатия «Применить» каталог
не меняется.

## Шаблон

`data/templates/catalog-import-template.xlsx` (второй лист — описание колонок) и `.csv`. Их же можно скачать в
админке. Одна строка = один SKU в одной аптеке. Если SKU есть в нескольких аптеках — несколько строк с одинаковыми
полями товара и разными `pharmacy_code`.

| Колонка | Обязательна | Описание |
|---|---|---|
| `external_id` | одно из трёх | ID в учётной системе — основной ключ сопоставления (внутри источника) |
| `salamat_sku` | одно из трёх | артикул SALAMAT |
| `barcode` | одно из трёх | EAN/GTIN, 8–14 цифр |
| `product_name` | да | торговое название (группирует варианты в одну карточку вместе с брендом) |
| `full_variant_name` | да | точное наименование SKU: «Название 500 мг №20 табл.» |
| `category_path` | | «Лекарственные средства > Обезболивающие»; недостающие категории создаются |
| `brand`, `manufacturer` | | бренд создаётся при необходимости |
| `dosage`, `form`, `package_size`, `volume` | | для различения вариантов и фильтров |
| `prescription_status` | | `rx` / `otc` / пусто. Пусто или нераспознанное → «не подтверждён» |
| `pharmacy_code` | для цены и остатка | код филиала (`SAL-01` … `SAL-14`, см. «Филиалы» в админке) |
| `price_kzt` | | целое число тенге > 0; «1 250» и «1250,00» допустимы |
| `stock_quantity` | | целое ≥ 0 |
| `image_url` | | только `https://`, только из источника с правом использования |
| `source_name` | | для справки |
| `updated_at` | желательно | момент актуальности цены/остатка: ISO 8601 или `ДД.ММ.ГГГГ ЧЧ:ММ` (время Астаны). Без даты — время импорта (с предупреждением). Дата в будущем — ошибка |
| `old_price_kzt` | | подтверждённая прежняя цена; показывается, только если выше текущей |
| `stock_status` | | `in_stock` / `low_stock` / `out_of_stock` / `on_request` — если количество неизвестно |
| `product_name_kk` | | подтверждённое казахское название; без него показывается оригинальное |
| `search_aliases` | | варианты написания через `;` |

Файлы CSV: UTF-8 или Windows-1251 (определяется автоматически), разделитель `,` или `;`. Старый формат `.xls`
не поддерживается — сохраните как `.xlsx`.

## Проверки

Строка **отклоняется** (не загружается, попадает в отчёт), если: нет названия или полного наименования; нет ни
одного идентификатора; неизвестный код аптеки; некорректная цена или остаток; цена/остаток без кода аптеки;
некорректная дата или дата в будущем; дубликат той же пары «SKU + аптека» в файле; артикул указан с разными
`external_id`; штрихкод совпадает с несколькими существующими SKU; значение длиннее допустимого.

**Предупреждения** (строка загружается): штрихкод не похож на GTIN, нераспознанная рецептурность, некорректная
ссылка на изображение (поле пропускается), прежняя цена не выше текущей, нет даты обновления, неизвестные колонки.

Отчёт об ошибках скачивается в CSV (`row_number, severity, column, code, message, raw_value`).
Если нет обязательных колонок, импорт сразу получает статус «Ошибка».

## Сопоставление и обновление

1. `external_id` в рамках того же источника (код источника задаётся при загрузке);
2. иначе `salamat_sku`;
3. иначе `barcode`, если ему соответствует ровно один SKU;
4. иначе создаётся новый SKU. Карточка товара ищется по названию и бренду, иначе создаётся.

Правила обновления:

* существующие SKU обновляются на месте, дубликаты не создаются; повторный импорт того же файла даёт
  «без изменений»;
* пустое поле в файле не стирает заполненное значение (кроме полного наименования);
* подтверждённая рецептурность не сбрасывается в «не подтверждён» пустым значением;
* товары, которых нет в очередном файле, **не удаляются и не снимаются с публикации**;
* новые товары создаются **черновиками** и не видны на сайте, пока менеджер не нажмёт «Опубликовать проверенные
  товары» на странице импорта (или не отметит «Сразу публиковать» при загрузке);
* применение идёт пакетами по 200 строк в транзакции; при сбое импорт получает статус «Ошибка» с сообщением,
  применённые пакеты остаются, повторная загрузка того же файла безопасна.

История импортов, счётчики (добавлено / изменено / без изменений / отклонено), автор и время хранятся в
`ImportJob`; применение пишется в журнал изменений.

## Экспорт

`/admin/import → Экспорт каталога (CSV)` или `GET /api/admin/export` — каталог в том же формате (строка на
SKU × аптеку). Подходит как шаблон для массового редактирования.

## API учётной системы

Задайте `CATALOG_API_URL` и `CATALOG_API_TOKEN` (передаётся как `Authorization: Bearer …`). Эндпоинт должен
отвечать JSON:

```json
{ "rows": [ { "external_id": "1C-000123", "product_name": "…", "full_variant_name": "…", "pharmacy_code": "SAL-01", "price_kzt": 450, "stock_quantity": 25, "updated_at": "2026-11-14T09:00:00+05:00" } ] }
```

с теми же именами полей, что в шаблоне. Другой формат подключается новым классом, реализующим `DataProvider`
(`src/server/import/providers.ts`). Интеграции, разбирающие HTML чужих сайтов, не допускаются.

## Демо-набор

`npm run db:demo` загружает 30 вымышленных SKU через этот же конвейер под источником `demo` (`isDemo=true`).
Такие товары не попадают в sitemap и видны на витрине только при `SHOW_DEMO_DATA=true`.
