# Архитектура

## Маршруты

Русская версия — без префикса, казахская — с префиксом `/kk` (код языка ISO 639-1 — `kk`; в переключателе
подпись «KZ», как просил бренд), английская — с префиксом `/en`. Это даёт отдельные URL для каждого языка,
корректные `hreflang` (ru-KZ, kk-KZ, en, x-default) и canonical. `src/proxy.ts` (в Next.js 16 так называется
middleware) внутренне переписывает `/catalog` → `/ru/catalog`, перенаправляет `/ru/...` на адрес без префикса и
запоминает явный выбор языка (`?lang=` или переключатель) в cookie. Список языков — `src/lib/i18n/config.ts`.

Английская версия переводит весь интерфейс (`src/lib/i18n/en.ts`). Данные без подтверждённого перевода — названия
товаров, артикулы, адреса аптек, юридические сведения, тексты акций и страниц из админки — показываются в исходном
виде (`pickLocalized`: казахский, если он есть, иначе оригинал на русском) с атрибутом `lang="ru"`. Страницы
«О компании», «Помощь» и др. на английском получают английский заголовок и пометку, что текст пока на русском.
Названия разделов каталога и города переведены отдельно (`categoryName`, `cityName`), неизвестные — в оригинале.

| Маршрут | RU | KZ (EN — то же с `/en`) |
|---|---|---|
| главная | `/` | `/kk` |
| каталог, категория | `/catalog`, `/catalog/[categorySlug]` | `/kk/catalog/...` |
| товар | `/product/[slug]?sku=[variantSlug]` | `/kk/product/...` |
| поиск | `/search?q=` | `/kk/search?q=` |
| корзина, оформление, подтверждение | `/cart`, `/checkout`, `/order/success/[publicId]` | `/kk/...` |
| аптеки | `/pharmacies`, `/pharmacies/[slug]` | `/kk/...` |
| акции | `/promotions`, `/promotions/[slug]` | `/kk/...` |
| страницы | `/about`, `/contacts`, `/help`, `/privacy`, `/terms` | `/kk/...` |
| избранное (дополнительно) | `/favorites` | `/kk/favorites` |
| админ-панель | `/admin/...` (только RU) | — |

Карточка товара — одна страница на торговое наименование; вариант (дозировка/форма/упаковка) выбирается
параметром `sku`, каждый вариант — отдельная строка в списке с точным наименованием. В каталоге и поиске каждая
карточка — это SKU, поэтому разные дозировки не сливаются.

## Данные

PostgreSQL, Prisma, миграции в `prisma/migrations`. Основные сущности (`prisma/schema.prisma`):

* **Product** — торговое наименование; **ProductVariant** — SKU (точное наименование, дозировка, форма, объём,
  упаковка, GTIN, артикул, внешний ID источника, рецептурность `PRESCRIPTION | NON_PRESCRIPTION | UNKNOWN`,
  `searchText` для поиска, `lastVerifiedAt`). Название никогда не используется как идентификатор:
  уникальны `slug`, `salamatSku`, пара `(sourceId, externalId)`.
* **Price** и **Inventory** — по паре `(variantId, pharmacyId)`, с источником и `sourceUpdatedAt` (когда данные
  были верны по источнику). `oldPriceKzt` — только настоящая прежняя цена.
* **Pharmacy** (город, адрес RU/KZ, исходная строка адреса, телефоны, координаты, часы работы JSON, дата проверки),
  **City**, **Category** (дерево, RU/KZ), **Brand**, **DataSource** (включая флаг `isDemo`).
* **Promotion** + связи с SKU, категориями, аптеками; тип выгоды `DISCOUNT | BONUS | OTHER`.
* **Order** (публичный номер `S-XXXX-XXXX`, ключ идемпотентности, контакты, согласие с версией политики, хеш IP)
  + **OrderItem** (снимок названия, количества, подтверждённой цены, наличия и рецептурности) + **OrderEvent**
  (история статусов) + **OrderNote** (служебные заметки).
* **AdminUser**, **Role**, **AdminUserRole**, **AdminUserPharmacy**, **AdminSession**.
* **ImportJob**, **ImportRow** (план предпросмотра), **ImportError** (отчёт).
* **ContentPage**, **FAQItem**, **SiteSetting**, **AuditLog**, **RateLimitBucket**.

Индексы: триграммный GIN по `ProductVariant.searchText` (расширение `pg_trgm`), индексы по категории, бренду,
форме, `(pharmacyId, priceKzt)`, `(pharmacyId, status)`, статусам заявок.

## Ключевые бизнес-правила

`src/lib/offer.ts → computeOffer()` — единственное место, которое решает, что показать для SKU в аптеке:

| Данные | Цена | Наличие | Кнопка |
|---|---|---|---|
| аптека не выбрана | «от X ₸ в N аптеках» (только свежие цены) или «Цена уточняется» | — | «Выбрать аптеку» |
| свежие цена и остаток > 0 | цена | «Есть» / «Осталось мало» | «В корзину» |
| цены нет | «Цена уточняется» | как есть | «Уточнить наличие» (позиция идёт в заявку без цены) |
| остаток неизвестен | цена | «Наличие уточняется» | «Уточнить наличие» |
| цена/остаток старше порога (72/24 ч, настраивается) | цена с пометкой «требует подтверждения» | «требует подтверждения» | «Уточнить наличие» |
| остаток 0 (свежий) | цена | «Нет в наличии» | «Нет в этой аптеке» + список других аптек |
| рецептурный, политика «запрет» (по умолчанию) | | | телефон аптеки, онлайн-заявки нет |
| товар каталога `pharmacy_products` (без цен по аптекам) | «Цена уточняется» | показывается, только если известно | «В корзину» → строка «цену уточнит аптека» |

Заявка (`src/server/orders/create.ts`): Zod-валидация → нормализация телефона → идемпотентность по ключу →
ограничение частоты (5 за 10 минут и 20 за сутки с одного хеша IP) → **повторный расчёт цен и наличия** → если что-то
изменилось или стало недоступно — ответ 409 с новым расчётом, заявка не создаётся → транзакция со снимками
позиций → после ответа (`after()`) — e-mail оператору без персональных данных. Отказ e-mail не теряет заявку:
ошибка пишется в заявку и видна в админке.

## Безопасность

* Пароли — scrypt (N=16384, r=8, p=1, соль 16 байт), проверка с постоянным временем; политика: ≥ 10 символов,
  буквы и цифры. Блокировка на 15 минут после 5 неудачных попыток, ограничение 20 попыток входа с IP за 15 минут.
* Сессии — случайный токен 256 бит в httpOnly-cookie (SameSite=Lax, Secure в production), в БД хранится только
  SHA-256 токена; срок 12 ч со скользящим продлением. Смена ролей завершает сессии сотрудника.
* Права проверяются на сервере: страницы — `requireStaffPage(permission)`, действия — `guarded(permission, …)`,
  API — `requireStaff()`. Область филиалов для менеджеров филиалов и операторов проверяется на уровне записи.
  Скрытие пунктов меню — только удобство.
* Публичные POST-эндпоинты проверяют Origin; server actions защищены механизмом Next.js.
* Все SQL-запросы параметризованы (`Prisma.sql`), LIKE-шаблоны экранируются.
* Markdown страниц рендерится без HTML (react-markdown), JSON-LD экранируется.
* Заголовки: CSP (production), X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy; `/admin` — `noindex`,
  `no-store`, `X-Frame-Options: DENY`.
* Персональные данные: в заявке — только имя, телефон, комментарий; IP хранится как HMAC-хеш; в журнал изменений и
  логи контакты не пишутся; оператор видит контакты, контент-менеджер — нет; обезличивание по сроку хранения
  (`runRetention`, cron `/api/cron/retention`, по умолчанию 180 дней).
* CSV-экспорт защищён от формульных инъекций Excel.

## SEO и производительность

* Уникальные `title`/`description`, canonical, `hreflang` (ru-KZ, kk-KZ, x-default), Open Graph.
* `sitemap.xml` — только опубликованные товары не из демо-источника, активные категории и акции, страницы без
  пометки «юридический черновик». `robots.txt` закрывает `/admin`, `/api`, корзину, оформление, заявки, избранное
  и поиск; пока не задан `ALLOW_INDEXING=true`, закрыт весь сайт и страницы помечены `noindex`.
* JSON-LD: BreadcrumbList, Product (без цен — они зависят от аптеки), Pharmacy, FAQPage.
* Каталог и поиск — серверная пагинация (24 на страницу), фасеты считаются в SQL; браузер получает только
  текущую страницу. Подсказки — 7 SKU + 3 категории.
* Шрифт локальный с `unicode-range`; изображения товаров — `next/image` для разрешённых хостов (`IMAGE_HOSTS`).

## Расширение

* Новый город: запись в `City`, филиалы привязываются к нему; переключатель города в шапке рассчитан на список.
* Учётная система: `HttpJsonDataProvider` (`CATALOG_API_URL`) или новый класс `DataProvider` — все источники
  проходят одну валидацию и один конвейер импорта.
* Онлайн-оплата: реализовать `PaymentProvider` в `src/server/payments/provider.ts` после договора с банком.
* SMS-уведомления: по аналогии с `notify.ts`.
